# AI 이상 감지 (사이클 시간)

PLC 트윈이 내보내는 `cycle.completed` 이벤트의 사이클 시간으로 설비 이상을 감지합니다.
감지 결과는 `ai.judgement`(판정)와 `alarm.raised` / `alarm.cleared`(경보) 이벤트로 발행되고, MES의 `machine_event`에 쌓입니다.
MES의 **현장모니터링** 페이지에서 볼 수 있습니다.

## 안전 원칙

AI는 판정과 경보만 냅니다. 설비를 멈출지는 PLC가 최종 판단합니다. `ai.judgement`의 `interlock_requested`는 요청 표시일 뿐이고,
PLC 로직에 연결되어 있지 않습니다.

## 방법 (`src/anomaly.py`)

- **특징값**: 사이클 시간 - 가공 시간(D10 설정). 가공 시간을 바꿔도 이상으로 보이지 않습니다.
- **학습**: 처음 8사이클의 중앙값을 기준값, MAD(중앙값 절대편차) x 1.4826을 산포로 씁니다. 산포에는 최솟값을 둡니다: max(0.05초, 기준값의 4%). 이상값에 강합니다.
- **점 판정**: z = (값 - 기준값) / 산포 가 6을 넘으면 이상 (갑작스러운 변화)
- **추세 판정**: EWMA(람다 0.3)의 z가 4를 넘으면 이상 (서서히 나빠지는 열화). 단, 현재 사이클도 같은 방향으로 1 산포 넘게 벗어나 있어야 합니다.
- **빨라지는 쪽은 점수를 절반으로** 봅니다. 설비 이상은 대개 느려지는 쪽이고, 크게 빨라지면(단계 누락 의심) 여전히 이상으로 잡습니다.
- **경보**: 이상이 연속 2회면 발생, 정상 범위(|z| < 3)가 연속 3회면 해제
- 학습 구간에 결함이 섞이면 기준값이 틀어지므로, 트윈 화면의 **기준 다시 학습**으로 다시 학습할 수 있습니다.

## 결함 주입 (시뮬레이터)

트윈 화면의 **결함 주입(시뮬레이터)** 에서 고릅니다. 주입과 해제는 `sim.fault` 이벤트로 기록되어, 감지가 맞는지 확인하는 기준이 됩니다.

| 모드 | 내용 |
|---|---|
| `cyl_slow` | 실린더 이동 시간 3배 (사이클 6.4초 -> 9.4초) |
| `cyl_degrade` | 사이클이 시작될 때마다 이동 시간이 조금씩 늘어남 (서서히 열화) |
| `sensor_flaky` | 도착 센서가 30% 확률로 0.7~1.5초 늦게 켜짐 |

## 검증 결과 (`python tests\test_anomaly.py`)

| 상황 | 결과 |
|---|---|
| 정상 운전 5분 (사이클 37회) | 오탐 경보 0건 |
| 정상 합성 데이터 120회 | 경보 0건 |
| **실측 정상 데이터 146사이클** (학원 PC, 결함 없음) | 예전 설정은 경보 2건(오탐), 현재 설정은 0건 |
| 실린더 속도 저하 | 주입 16초 뒤 경보 (사이클 2회), 해제 후 약 20초 뒤 경보 해제 |
| 점진 열화 | 주입 32초 뒤 경보, 그때 사이클은 정상보다 +0.75초 (2초 넘게 늘어나기 전에 감지) |
| 센서 응답 지연(간헐) | 주입 22초 뒤 경보 |
| 가공 시간 설정 변경 (3.0 -> 2.0초) | 오탐 없음 |

수치는 시뮬레이터에서 잰 값이며 실제 장비와는 다를 수 있습니다.

### 실제 사용 중 발견해서 고친 오탐

처음에는 산포의 최솟값을 0.05초로 두고 양쪽에 같은 임계값을 썼습니다. 시뮬레이터 측정에서는 오탐이 0건이었지만,
학원 PC에서 실제로 돌려 보니 컴퓨터 부하에 따라 사이클 시간이 3.51~3.70초 사이에서 이동했고(-0.15초), 이것이 이상으로 판정되어 오탐 경보가 났습니다.
또 한 사이클이 +4초로 튄 뒤에는 EWMA의 꼬리 때문에 정상 사이클 뒤에도 이상 판정이 이어져 경보가 났습니다.
그래서 (1) 산포 최솟값을 기준값의 4%로 올리고, (2) 빨라지는 쪽은 점수를 절반으로 보고, (3) 추세 판정에 "현재 값도 같은 방향으로 벗어나 있을 것"을 추가했습니다.
실측 146사이클을 `tests/data/real_healthy_cycles.json`로 저장해서, 이 오탐이 다시 생기지 않는지 `tests/test_anomaly.py`가 확인합니다.

## 화면

MES **현장모니터링**: AI 상태 / 활성 경보 / 최근 사이클 / 기준값 카드, 사이클 시간 추이(정상 범위와 결함 주입 시점 표시),
이상 점수 그래프, 감지 검증 표(결함 주입 -> 경보까지 걸린 시간), 경보 이력, 최근 AI 판정. 트윈 화면을 위에 끼워 넣어서 같은 페이지에서
결함을 주입하고 감지되는 모습을 볼 수 있습니다.

설치: `python src\mes_adapter.py --install-addons` (기존 `13_현장모니터링.py`는 `13_현장모니터링.py.orig`로 백업됩니다)

## 한계와 확장

- 사이클 시간 하나만 봅니다. 진동, 전류 같은 신호가 있으면 IsolationForest 같은 다변량 모델로 확장할 수 있습니다.
- 학습은 서버를 다시 켤 때마다 처음부터 합니다 (기준값을 저장하지 않음).
- 비전 검사(YOLO 등)는 같은 `ai.judgement` 형식(`model` 필드만 다르게)으로 붙일 수 있도록 열어 두었습니다.
