# 스마트 팩토리 통합 화면

가공 라인(PLC), 프레스 · 용접 · 도장 라인, **물류 · 출하 구역**(`logistics.md`), **협동로봇 팔레타이징 셀**(`cobot.md`)을 **한 3D 화면**에 놓고 라인별 상태를 함께 봅니다.

- 열기: 트윈 서버를 켜고 http://localhost:5001/3d/factory (각 3D 화면의 "공장 전체" 링크, 주소 옵션 `?embed=1`, `?embed=view`)
- **전체** 버튼은 두 라인이 모두 보이게 창 크기에 맞춰 카메라를 맞추고, **라인 이름** 버튼은 그 라인으로 확대합니다.
- 왼쪽 카드: 라인별 상태(가동, 정지, AI 이상 감지 경보), 카운트, 처리량, 병목과 **시작, 정지, 리셋** 같은 조작 버튼
- 아래쪽: 시점, 이름표 켜기/끄기, **용어**(현장 용어 / 장비 원명칭) 전환

## 구조

```
src/scenes/machining.json           가공 라인 3D 장면 (tools/make_machining_scene.py 로 만듦)
src/scenes/press_weld_paint.json    프레스 라인 3D 장면
src/scenes/logistics.json           물류 · 출하 구역 3D 장면 (tools/make_logistics_scene.py)
src/scenes/cobot.json               협동로봇 팔레타이징 셀 3D 장면 (tools/make_cobot_scene.py)
src/scenes/factory.json             라인별 위치(offset), 카메라
/api/factory/state                  라인별 상태를 한 번에 {machining: ..., press: ..., logistics: ..., cobot: ...}
src/static/factory.js               위 파일들을 읽어 한 장면에 그리는 범용 뷰어
```

새 라인은 장면 JSON, 상태, `factory.json` 한 줄이면 이 화면에 들어옵니다. 물류 · 출하 구역이 그렇게 들어와 있습니다. 형식은 `scene_format.md`.

## 시험

`python tests\test_factory.py`: 장면 JSON의 모든 path가 서버 상태에 있는지, 가짜 three.js 에서 뷰어를 돌려 두 라인의 배치(offset), 실린더 로드 길이, 부품 위치와 색, 스택 라이트, AI 경보 조명, 요약 카드, 용어 전환을 확인합니다.
(실제 화면 모양은 브라우저에서 확인해야 합니다.)

## 알려진 한계

- 기존 단일 라인 화면(`/3d`, `/3d/line`)은 그대로 두고 있고, 통합 화면과 같은 장면 JSON을 쓰는 쪽으로 합칠 수 있습니다.
- 라인을 클릭해서 확대하는 기능은 버튼으로 대신했습니다.
- 세 구역의 **배치(offset)는 임시값**입니다 (`factory.json`). 실제 공장처럼 공정 구역 사이를 대차, AGV로 잇는 것은 아직 하지 않았습니다.

## MES 공장현황 대시보드

MES 쪽에서 세 구역을 숫자로 보는 페이지는 `dashboard.md`를 보세요 (3D 공장 화면이 위에 들어 있습니다).

## 데모 모드 (영상 녹화용)

`/3d/factory` 아래쪽 막대의 **▶ 데모** 버튼(또는 주소 뒤에 `?demo=1`)을 누르면 약 90초짜리 시연이 자동으로 진행됩니다. 화면 위쪽에 단계 설명이 뜨고, 카메라가 부드럽게 이동합니다.

| 단계 | 시점 | 자동으로 하는 일 |
|---|---|---|
| 1 | 전체 | 라인 리셋, 배속 3 |
| 2 | 가공 라인 | 가공 라인 연속 동작 |
| 3~5 | 프레스, 용접, 도장 (세부 시점) | 프레스 · 용접 · 도장 라인 시작 |
| 6 | 협동로봇 셀 | 비전 검사, 파렛트 적재 |
| 7~9 | 입고, AGV, 출하 | 입고 요청, 출하 트럭이 4개 차면 출발 |
| 10~11 | 프레스 라인 | 용접 속도 저하 결함 주입 후 해제 |
| 12 | 전체 | 마무리 |

세부 시점은 `?focus=press:weld`, `?focus=logistics:inbound`처럼 `구역:시점` 이름으로도 열 수 있습니다. 시나리오는 `src/static/factory.js`의 `DEMO_STEPS`에서 고칩니다.
녹화 전에는 `--reset-demo`로 MES 데이터를 비우고 시작하세요.

## 공장 전체 수치 박스와 캡처

`/3d/factory` 오른쪽 위에 공장 전체 수치 박스가 뜹니다 (아래 막대의 **수치** 체크로 끕니다). 라인별 카드가 라인 하나의 숫자를 보여 주는 것과 달리, 여러 구역의 핵심 수치를 한 곳에 모읍니다.

| 줄 | 내용 |
|---|---|
| 프레스 라인 | 양품, 불량(불량률), 가동/정지 |
| 가공 라인 | 양품, 불량, AI 상태 |
| 협동로봇 셀 | 비전 검사, 불량, 완성 파렛트 |
| 출하 | 출하 개수, 출하 트럭 적재(예: 2/4) |
| 원자재 | 정상 또는 부족한 자재 이름 |
| 결함 | 결함을 주입한 동안에만 표시 |

**📷 캡처** 버튼은 지금 3D 화면에 수치 박스와 데모 설명(데모 중일 때)을 그려 넣은 PNG를 `smart-factory_날짜_시각.png`로 내려받습니다. README와 보고서 스크린샷용입니다. 창 크기를 키워서(전체 화면) 캡처하면 해상도가 높아집니다.

## 재공품(WIP) 표시 (프레스 · 용접 · 도장 라인)

라인 안에 있는 부품(재공품)을 눈으로 볼 수 있습니다.

- **바닥의 "재공품 현황" 띠**: 프레스, 컨베이어1, 용접, 컨베이어2, 도장, 컨베이어3 칸 6개가 색으로 상태를 보여 줍니다. 어두운 색 = 비어 있음, 초록 = 작업 중, **노랑 = 일을 마쳤는데 다음 칸이 차서 기다림**, 빨강 = 설비 정지.
- **기다리는 부품은 노란색**으로 칠해집니다. 병목인 도장 앞에서 용접을 마친 부품이 기다리고, 도장을 멈추면(결함 주입) 뒤쪽이 막혀 부품이 쌓이는 모습이 보입니다.
- 라인 카드와 수치 박스에 **재공품 수(기다리는 수)** 가 나옵니다. 상태 값은 `occ.<칸>`(empty, working, waiting, down), `kpi.wip`, `kpi.waiting`입니다.

## 가공 라인 3D 디테일

- **실린더 부속**: 공급, 이송, 분류 실린더에 양쪽 캡, 에어 포트, 리드 스위치 LED가 붙어 있습니다. LED는 PLC 입력 X0~X7(실린더 뒤/앞 위치)에 연결되어, 켜진 쪽이 지금 실린더 위치입니다.
- **드릴링 유닛**: 모터 냉각 핀, 상단 캡, 스핀들 슬리브, 지지대의 상하 한계 LED(X2 아래, X3 위).
- **센서 스테이션**: 컨베이어 입구 위에 유도형(금속, X9, 빨강)과 정전용량형(비금속, X0A, 파랑) 센서와 브래킷.
- **컨베이어 구동 모터**(벨트가 돌 때 불이 켜짐, Y27), **제어반**(시작 · 정지 · 비상정지 버튼, 가동 · 경보 표시등), **에어 유닛**(필터, 레귤레이터, 압력계).
- 장면은 `tools/make_machining_scene.py`로 만들고, `tests/test_machining_scene.py`가 연결과 겹침을 숫자로 검사합니다.
